## 2. Item Typeの設計方針

### 基本方針

`item_type` は基本的に運営側が定義するマスタとする。

現時点では病院ユーザー側からItem
Typeそのものを任意追加・編集することはできない。

ただし、Item Typeとして「任意の選択肢」を用意し、このItem
Typeを選択した場合のみ、病院ユーザー側で点検項目ごとの選択肢を追加・編集できるようにする。

### UI決定

点検入力画面では `input_type` によってUIを決定する。

現在の想定：

  Item Type      input_type     UI
  -------------- -------------- ------------------
  数値入力       `number`       数値入力
  OK/NG          `two_choice`   専用2択UI
  実施/未実施    `two_choice`   専用2択UI
  ON/OFF         `two_choice`   専用2択UI
  レ点           `checkbox`     チェックボックス
  任意の選択肢   `select`       Select

### 2択UIについて

`select`では2回タップが必要になるため、OK/NGなどの2択は専用UIを使用する。

専用2択UIはReact標準のプリセットではなく、アプリ内で共通コンポーネントとして作成する方針。

2択UIでは、

-   1タップで入力できる
-   未選択状態を表現できる
-   未確認とOK/NGなどを区別できる

ようにする。

未選択はデータ上 `null` とする想定。

## 3. DB変更

`inspection_item_types` に以下のcolumnを追加。

``` sql
ALTER TABLE inspection_item_types
ADD COLUMN is_custom_option boolean NOT NULL DEFAULT false;
```

既存の「任意の選択肢」だけ `true` に設定。

``` sql
UPDATE inspection_item_types
SET is_custom_option = true
WHERE name = '任意の選択肢';
```

また、既存の2択系Item Typeの `input_type` を `two_choice` に変更。

``` sql
UPDATE inspection_item_types
SET input_type = 'two_choice'
WHERE name IN (
    'OK/NG',
    '実施/未実施',
    'ON/OFF'
);
```

### `is_custom_option` の役割

`input_type`： → 点検入力時にどのUIを表示するかを決める。

`is_custom_option`： → 選択肢をユーザー側で設定できるItem
Typeかどうかを決める。

この2つの責務を分離する。

## 4. Frontend Type

`inspectionItemTypeTypes.ts` を更新。

### Response

FrontendではcamelCaseを使用。

``` ts
export type InspectionItemType = {

    id: number
    name: string
    description: string | null
    inputType: string
    isCustomOption: boolean
    options: string[] | null
    isActive: boolean

}
```

Backend/DB側はsnake_case。

``` ts
export type InspectionItemTypeDB = {

    id: number
    name: string
    description: string | null
    input_type: string
    is_custom_option: boolean
    options: string[] | null
    is_active: boolean

}
```

### Add / Update

プロジェクトの命名規則に合わせて、

-   `AddInspectionItemFrontType`
-   `AddInspectionItemBackType`
-   `UpdateInspectionItemFrontType`
-   `UpdateInspectionItemBackType`

を使用する。

FrontTypeはcamelCase、BackTypeはsnake_caseとする。

## 8. Transaction

`inspection_item_types`
は単一テーブル処理のためTransaction自体の意味は薄いが、構造を統一するため、Fetch以外をTransaction化した。

作成したもの：

``` text
add_inspection_item_type_transaction.py
update_inspection_item_type_transaction.py
delete_inspection_item_type_transaction.py
```

基本的な流れ：

``` text
Route
 ↓
Transaction
 ↓
CRUD
 ↓
Fetch
 ↓
最新一覧を返す
```

### 実装内容

